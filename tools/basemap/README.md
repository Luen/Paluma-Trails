# Basemap pipeline

Produces the offline basemap assets in `content/basemap/`:

| File | Size | Source | Licence |
| --- | --- | --- | --- |
| `paluma.pmtiles` | 1.5 MB | [Protomaps](https://protomaps.com) daily build (OSM data), extracted for `146.05,-19.11,146.33,-18.80`, zooms 0–15 | data © OpenStreetMap contributors, ODbL 1.0; tooling ISC |
| `style.json` | 170 KB | Generated by `generate_style.mjs` from `@protomaps/basemaps` (light theme) | ISC |
| `fonts/…` | 0.9 MB | Protomaps basemaps-assets, Noto Sans Regular/Medium/Italic (stored as `Noto-Sans-*` because Flutter web asset paths must not contain spaces), Latin ranges only | SIL OFL 1.1 |
| `sprites/light*` | 50 KB | Protomaps basemaps-assets | ISC |

These files are **committed on purpose**. At 2.4 MB in total they make a fresh
clone, CI and the shipped app work fully offline with no build-time downloads, no
API keys and no tile server. Regenerate them only when deliberately updating the
map data:

```bash
brew install pmtiles node        # once
cd tools/basemap && npm install @protomaps/basemaps
PROTOMAPS_BUILD=20261015 ../../tools/basemap/build_basemap.sh
cd ../.. && dart run tools/paluma_cli/bin/paluma_cli.dart bundle build
```

`build_basemap.sh` is the supported entry point. If you invoke
`generate_style.mjs` yourself, run it from the **repository root** with a path
relative to that root (for example `content/basemap/style.json`). The script
refuses absolute paths outside the working directory.

`PROTOMAPS_BUILD` is a build date from <https://build.protomaps.com> (a new
`YYYYMMDD.pmtiles` appears daily). The script writes only the park's tiles, using
HTTP range requests, so it downloads ~1.6 MB rather than the whole planet.

## How the app consumes these files

The style contains two placeholders:

- `PALUMA_PMTILES` — the archive. Native: `pmtiles://file://<documents>/basemap/paluma.pmtiles`;
  web: `pmtiles://<origin>/assets/assets/bundle/basemap/paluma.pmtiles` with the
  protocol registered by `maplibre_gl_web`.
- `PALUMA_ASSETS` — directory containing `fonts/` and `sprites/`, resolved the
  same way.

On first launch the app copies `assets/bundle/basemap/**` into its documents
directory (native only — the browser keeps assets where they are) and rewrites
the placeholders, because MapLibre Native cannot read Flutter assets directly.
This also gives us the mechanism for the incremental bundle download in issue
#17: same layout, different source directory.

## Changing the area or detail

- Park bounds live in `content/data/paluma/park.json` and the script's `PALUMA_BBOX`.
- Raising `MAX_ZOOM` above 15 requires a source with deeper tiles: the Protomaps
  planet build stops at z15. Deeper detail can come from a
  [protomaps/planetiler](https://github.com/protomaps/planetiler) run against the
  Queensland region, or from Queensland Government QTopo data (see issue #16).
